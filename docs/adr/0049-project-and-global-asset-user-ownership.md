# 项目与全局资产按用户隔离

## Context

ADR 0021 只预埋了部分数据库表的 `user_id`，项目目录和全局资产仍是实例级共享；JWT 也没有携带数据库用户 ID。多用户登录启用后，任一已认证用户都可能通过项目名、资产 ID、任务 ID 或媒体 URL 访问其他用户的数据。

## Decision

- JWT 与 API Key 的认证结果必须包含正整数 `user_id`。旧 JWT 缺少该声明时要求重新登录，不猜测身份。
- 项目名继续保持实例内全局唯一，项目目录布局不变。项目所有者记录在数据根目录的 `_project_owners.json`，写入使用文件锁和原子替换；存量未登记项目归默认用户 `1`。
- 所有带 `project_name` 的认证请求在统一认证依赖处校验项目所有权。请求体内的项目名在对应路由显式校验。不存在和无权访问统一返回 404，避免泄露项目是否存在。
- 全局资产数据库以 `(user_id, type, name)` 唯一，Repository 强制用户作用域；新资产文件存入 `_global_assets/{user_id}/{type}/`。旧 `_global_assets/{type}/` 路径仅允许默认用户读取。
- 项目关联任务和用量按用户过滤。Web 请求显式传入当前用户；智能体工具和未显式传用户的文本生成从项目所有权解析用户。
- 浏览器原生加载的项目媒体与全局资产 URL 使用短路径加当前登录 token 查询参数，因为 `<img>`、`<video>` 和 `<audio>` 无法附加应用层 `Authorization` 请求头。

## Consequences

- 这次变更实现所有权隔离，不实现角色权限、项目共享或管理员跨用户浏览。
- 项目名仍不能由不同用户重复使用；若未来需要每用户同名项目，应另行迁移到用户命名空间目录或不可变项目 ID。
- `_project_owners.json` 损坏时操作显式失败，不能静默回退到默认用户；只有缺少单个存量登记时才执行用户 `1` 兼容规则。
- 下载 token 除项目名外还绑定用户 ID，并在下载时重新检查当前所有者，防止同名项目删除重建后旧 token 越权。

## Supersedes

本 ADR 取代 ADR 0021 中“不实装多租户”和 `_scope_query` 为 no-op 的结论；仍保留默认用户 `1` 作为历史数据回填策略。
